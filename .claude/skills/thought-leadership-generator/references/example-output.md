# Exemple de sortie

Exemple fictif produit à des fins d’illustration. Les données ne correspondent à aucune personne ni organisation réelle.

## Angles proposés

| Angle | Prise de position | Format | Effort | Risque |
| --- | --- | --- | --- | --- |
| Le double run coûte plus cher que prévu, et c’est parfois le bon choix | Assume un surcoût volontaire | Post texte, 250 mots | Faible | Faible |
| Une gouvernance d’API écrite avant la première API ne survit pas | Contredit une pratique répandue | Post texte, 300 mots | Moyen | Moyen |
| Le décommissionnement n’échoue pas techniquement, il échoue sur l’arbitrage | Déplace la cause racine | Post texte, 200 mots | Faible | Faible |
| Ce que 18 mois de migration ont changé dans ma façon de découper un programme | Retour d’expérience personnel | Post long ou article | Élevé | Faible |
| Les indicateurs à instrumenter avant de toucher au socle | Contenu utilitaire | Post carrousel ou liste | Moyen | Faible |

## Angle développé

Sujet : le décommissionnement échoue sur l’arbitrage, pas sur la technique.

```text
Sur les programmes de remplacement de socle que j'ai vus échouer, la cause
n'était presque jamais technique.

Elle tenait à une question restée sans réponse : qui accepte de payer
le surcoût temporaire ?

Un double run coûte cher. Il double l'exploitation, il mobilise deux équipes,
il allonge le programme. Tant que personne n'assume ce coût explicitement,
le programme avance en évitant la décision, et il s'arrête au premier arbitrage
budgétaire.

Sur mon dernier programme, nous avons chiffré le double run avant de démarrer
et nous l'avons fait valider comme une ligne à part entière. Cela a allongé
la trajectoire de quatre mois. Cela a aussi évité qu'elle s'arrête au bout de six.

La question n'est pas de savoir si la migration est faisable.
Elle est de savoir qui porte le surcoût, et pour combien de temps.
```

## Contrôles appliqués

| Point | Statut |
| --- | --- |
| Prise de position, pas constat général | Oui, déplace la cause racine |
| Appuyé sur une expérience réelle | Programme fourni par l’utilisateur |
| Aucune auto-promotion | Aucun appel à contact, aucun nom d’employeur |
| Aucune tendance présentée comme un fait | Aucune statistique citée |
| Désaccord sur les idées | Aucune entreprise ni personne visée |
